# tamandua — project context

Local-first personal-finance app: Vite/React front end, Express + SQLite API (`src/`), MCP
endpoint served by the same process at `/mcp`. It also carries the Hermes skill that teaches
agents how to talk to it, at `.hermes/skills/tamandua/SKILL.md`.

## Write-target rules for skills (important)

`SKILL.md` is **method only** — it must read correctly for somebody else's tamandua install.

Never write these into `SKILL.md`, and never move them out of the profile file into it:

- names of Tiago, his partner, or anyone appearing on a statement;
- account, asset or category **ids** (they go stale — he edits them in the UI between runs);
- bank account numbers, BG/card numbers, ISINs of personal holdings;
- merchant→category mappings, "always/never categorize X" rules, or any other preference.

Those go in `.hermes/skills/tamandua/references/import-profile.md`. Read that file before
importing, categorising or recording dividends, and append new personal facts **there**, in the
matching section, updating the existing line instead of adding a contradicting one.

Procedural learnings do belong in `SKILL.md`, written impersonally: parsing quirks of a file
format, checksum and read-back discipline, MCP/REST gotchas, validation behaviour, pitfalls that
would apply to anyone's data. The test is "would this line still make sense if the user's name
and every id were removed?" — if not, it goes in the profile file.

Everything in this repo **except** `references/import-profile.md` is committed and shareable, so
it also names no bank, card issuer or broker: describe an export by its shape, and put the
who-uses-what mapping in the profile's source→recipe table. The literal description and notes
strings an import writes are personal data too — they identify the person's statements once rows
exist in the database.

`skills.external_dirs` is **not** write protection: Hermes modifies skills under it in place, so
these rules are the only thing keeping personal data out of a file that gets committed and shared.
Prefer a `references/` support file over a new bullet in `SKILL.md` whenever detail is only
needed for some tasks.

## Conventions

- Never read `data/portfolio.sqlite` directly, even to answer a question — go through the API
  or `/mcp`. `data/` is gitignored and holds the live database and backups.
- Money keeps its original currency everywhere; nothing is pre-converted in the backend.
- Prices are dated manual snapshots. The app does not call price providers.
